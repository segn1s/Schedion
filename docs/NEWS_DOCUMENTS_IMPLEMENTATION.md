# Новости, документы, офлайн и файлы

Локальная реализация задач #17, #23, #28, #29 и #33. Экран документов также заменён реальными данными, поскольку #23 и #17 включают этот раздел; это пересекается с #32.

## Данные и состояния

- Новости вынесены из ScheduleRepository в NewsRepository. DocumentsRepository отвечает за список категорий и детали документа. Оба интерфейса используются в тестах с заменяемым API.
- DTO сохраняются в Room как снимки конкретных запросов, затем преобразуются в доменные модели. Ключи различают страницы ленты, slug статьи/документа, группу/преподавателя и неделю расписания.
- Миграция Room 3 → 4 добавляет content_cache и downloads. Старые таблицы и данные не удаляются; destructive migration не используется. JSON-схема новой версии хранится в app/schemas.
- ContentState сводит Resource в состояние экрана: Loading сохраняет предыдущий контент, Error добавляет сообщение и повтор, успешный ответ заменяет снимок. Ошибка IOException даёт офлайн-плашку, HTTP 4xx/5xx — сообщение об ошибке сервера. Время снимка — фактический момент его записи, а не дата из макета.
- UiStateContent используется новостями, статьями, документами, расписанием и сообщениями справочников. Тексты находятся в строковых ресурсах.
- В расписании, поиске, новостях и документах общая плашка «Вне сети» показывает оранжевую иконку и, когда известно, время сохранения данных. Контуры иконки перенесены из I.offline в Anime_P/src/components/icons.jsx. Плашка появляется после 10 секунд непрерывного отсутствия подтверждённого доступа в интернет и исчезает при восстановлении связи. NetworkStatusViewModel сохраняет ожидание при переключении вкладок и повороте экрана. При восстановлении связи повторяются неудавшиеся сетевые запросы. NetworkMonitor использует ConnectivityManager и NET_CAPABILITY_VALIDATED с разрешением ACCESS_NETWORK_STATE. [Android Developers](https://developer.android.com/develop/connectivity/network-ops/reading-network-state)
- Для листания запрашиваются страницы по 5 записей, offset двигается по фактическому ответу сервера. Страницы объединяются с устранением повторов slug; конец списка определяется total и размером ответа. Неудачная следующая страница не стирает предыдущие.
- Навигация остаётся собственной и SingleActivity. Детальные маршруты содержат slug; стек и состояние прокрутки сохраняются средствами Compose при пересоздании Activity.

## HTML и изображения

- Новых зависимостей нет. Стандартный Android Html разбирает HTML и сущности; результат преобразуется в блоки Compose: текст с форматированием, заголовки, списки, цитаты, ссылки и изображения. Небольшой TagHandler сохраняет нумерацию и вложенность списков.
- WebView не используется. Скрипты не исполняются; script/style исключаются из отображаемого текста. Для внешних ссылок допускаются HTTP(S), Telegram, mailto и tel; для файлов и изображений — только HTTP(S).
- Относительные /files/... разрешаются относительно https://schedion.ru/. Обложки и картинки загружаются существующим OkHttp вне главного потока и сохраняются в кэше приложения. Ограничены размер ответа, размер декодированного изображения, память и дисковый кэш.
- Статья не дублирует обложку и те изображения вложений, которые уже присутствуют в HTML. Непросмотренная картинка без интернета может быть недоступна; просмотренная остаётся в кэше до его системной очистки/вытеснения.

## Файлы

- Загрузка выполняется DownloadManager в общедоступный каталог Downloads/Schedion. При minSdk 29 широкие разрешения на хранилище не требуются.
- Повторное скачивание той же версии повторно использует существующий downloadId. Версия определяется идентификатором материала, updatedAt/publishedAt и URL файла. Новая версия получает другую запись и имя.
- Реестр ID загрузок хранится в Room. Состояние DownloadManager опрашивается, пока экран наблюдает за загрузками; сами системные загрузки продолжаются после закрытия приложения.
- Для открытия и отправки используется content URI, возвращаемый самим DownloadManager, с временным FLAG_GRANT_READ_URI_PERMISSION. Дополнительный FileProvider не нужен: путь к локальному файлу другим приложениям не передаётся.
- Реализованы отправка ссылки без скачивания и отправка скачанного файла. Если файл удалён, обработчик формата не установлен или загрузка завершилась ошибкой, приложение показывает понятное сообщение/повтор.

## Проверка

Автоматические проверки: unit-тесты, Android Lint, сборка приложения и инструментальные тесты HTML, пагинации/отмены и миграции. Фактический результат запусков следует смотреть в итоговом сообщении задачи.

Полный сценарий ручного прогона: [MANUAL_TESTING_NEWS_DOCUMENTS.md](MANUAL_TESTING_NEWS_DOCUMENTS.md).

Публичный API во время реализации возвращал 7 новостей и пустой список документов. Пустое состояние документов проверяется на текущем сервере; проверка документов разных форматов и серверных ошибок требует подготовленных тестовых данных. Содержимое production API не изменялось.
